# 02 · 战术系统

## 设计目标

战术面板**完全参考 FM 的心智模型**（阵型 → 心态 → 攻防指令 → 每人一个角色+职责 → 定位球 → 临场调整），FM 玩家零学习成本。底层上，战术是一份**可序列化的参数包**，由战术编译器翻译成仿真核可执行的指令集；比赛进行中可**热替换**。

这条设计有一个重要推论：**玩家界面和 AI 经理调用同一套接口。** AI 教练会真的"想"战术、临场变阵换人——这是"两边纯 AI 也好看、AI 比 FIFA 聪明"的载体。

```
玩家/AI经理 ──设置──▶ 战术面板数据（JSON）──编译器──▶ SimParams ──▶ 仿真核
                          ▲                                        │
                          └────────── 临场热替换 ◀── 比赛事件 ──────┘
```

## 一、阵型（Formation）

- **槽位制**：阵型 = 11 个槽位，每槽位有归一化基准坐标（以本方球门为原点，x∈[0,1] 纵深，y∈[-1,1] 横向）。防守时锚点为基准位，进攻时按角色与球位做弹性偏移（偏移规则在角色里定义）。
- v1 预设 10 套：`4-4-2 / 4-4-1-1 / 4-1-4-1 / 4-2-3-1 / 4-3-3 / 4-2-4 / 3-4-3 / 3-4-2-1 / 3-5-2 / 5-3-2`。
- 阵型编辑器（拖拽槽位）放 v2；v1 靠预设 + 角色互换覆盖 90% 需求。

## 二、心态（Mentality，7 档）

心态是**一组全局参数的预设偏移**，具体数值如下（v1 校准用）：

| 参数 | 极端防守 | 防守 | 稳健 | 平衡 | 积极 | 进攻 | 极端进攻 |
|---|---|---|---|---|---|---|---|
| 防线基准高度（距本方球门） | 28m | 31m | 34m | 37m | 40m | 43m | 46m |
| 逼抢触发线 | 本方禁区前沿 | 本方 1/3 | 中线后 | 中线 | 中线前 | 对方 1/3 | 对方禁区前沿 |
| 向前传风险权重 | ×0.5 | ×0.7 | ×0.85 | ×1.0 | ×1.2 | ×1.4 | ×1.6 |
| 推进节奏（决策时间窗） | 1.4s | 1.2s | 1.1s | 1.0s | 0.9s | 0.8s | 0.7s |
| 阵型宽度 | 32m | 34m | 36m | 38m | 40m | 42m | 44m |
| 逼抢强度基准 | 1/5 | 2/5 | 2/5 | 3/5 | 4/5 | 4/5 | 5/5 |

角色职责会在此基础上做二次偏移（例如 4-4-2 平衡心态下，双前锋的职责默认不对称）。

## 三、有球指令（In Possession）

| 指令 | 档位 | 编译为 |
|---|---|---|
| 进攻宽度 | 窄 / 标准 / 宽 | 边路球员锚点横向偏移 ±3m/档 |
| 出球方式 | 后场短传 / 混合 / 直接 | 门将+中后场出球决策：短传成功率阈值（短传=宁可回传不冒险）、直接=长传权重 ×1.8 |
| 传球节奏 | 慢 / 标准 / 快 | 全队持球决策时间窗 ±20%（快=更早出球，误差略升） |
| 传中倾向 | 早传 / 混合 / 低平 / 少传中 | 边路传中触发条件（下底深度、包抄人数）与传中类型分布 |
| 进攻三区打法 | 渗透 / 混合 / 远射 / 套边传中 | 禁区前沿动作集权重（直塞/远射/套上） |
| 短传渗透倾向 | 关 / 开 | 连续短传推进链的容忍度（开=允许慢速倒脚，快节奏触发线后移） |
| 时间拖延 | 关 / 开（领先时） | 领先 + 70' 后自动叠加：节奏 ×1.25 放慢、向前风险 ×0.7 |

## 四、无球指令（Out of Possession）

| 指令 | 档位 | 编译为 |
|---|---|---|
| 防线高度 | 很低 → 很高（5 档） | 心态基准 ±4m/档；与越位线联动 |
| 防线宽度 | 窄 / 标准 / 宽 | 后卫线横向间距 ±2m/档 |
| 逼抢强度 | 很低 → 很高（5 档） | 逼抢启动距离 22m→8m；同时上抢人数 1→3；逼抢失败的退防速度 |
| 逼抢触发线 | 后场 / 中场 / 前场 | 优先发起围抢的球场区域（前场触发=对方半场就围抢） |
| 抢断强度 | 温柔 / 正常 / 凶狠 | 犯规概率 ×0.6 / ×1.0 / ×1.8；抢断成功率 ±10% |
| 越位战术 | 关 / 开 | 后卫线协同上提逻辑（开=造越位尝试 ↑，风险：被打身后） |
| 反抢 (Counter-Press) | 关 / 开 | 丢球后 5 秒内：丢球点半径 12m 内 2–3 人立即反抢 |
| 快速反击 (Counter) | 关 / 开 | 断球后 6 秒内：向前直塞与冲刺权重 ×2 |
| 门将发球 | 短传 / 混合 / 长传 | 球门球/持球出球方式（长传=目标点选择：中锋争顶或两翼） |
| 逼抢门将 | 关 / 开 | 前锋对门将持球时的施压距离 |

## 五、角色系统（Roles & Duties）——战术的灵魂

**角色 = 行为包**，由四部分组成：

1. **基准锚点函数**：球位 → 本档位的目标站位（比固定坐标先进：拖后组织核心的锚点会随球横向滑动）。
2. **有球动作权重**：该角色拿到球后各动作（直塞/横传/盘带/远射…）的效用权重覆盖。
3. **无球跑位规则**：本方控球时的跑位触发（套边、内切、插上禁区、回撤接应）。
4. **防守职责**：逼抢优先级、补位对象、盯人偏好。

### 角色清单（27 个，v1 先做 ⭐ 标记的 14 个）

> 角色后括号内为 data/tactics/roles.json 的机器 id，文档与数据 1:1 对应。

### 职责（Duty，3 档）

防守 / 策应 / 进攻，编译为：锚点纵深偏移（±4m/档）、无球插上触发时机（进攻档=本方拿球即插，防守档=球进对方三区才插）、防守投入度（进攻档=逼抢力度 −1 档）。

## 六、定位球

v1 为**预设制**，每队攻防各配一套：

| 类型 | 进攻预设 | 防守预设 |
|---|---|---|
| 角球 | 前点包抄 / 后点强攻 / 近门柱短角球战术 | 区域混合 / 全人盯人 / 前点挡拆 |
| 任意球（射门距离） | 直接射门 / 人墙配合直塞 / 45° 传中 | 人墙高度人数 / 横向站位 |
| 任意球（远离球门） | 长传进禁区 / 快发 | 造越位 / 收缩 |
| 界外球 | 快掷 / 手榴弹（需 Long Throws 属性） | 盯人 |
| 点球 | 主罚顺位表（按 Penalties 属性自动排序） | — |

主罚人自动选择：按 Corners/Free Kick/Passing 属性排序，可手动指定。定位球套路在仿真核里是**脚本化的走位序列 + 属性化执行**（详见 03 文档 §定位球）。

## 七、临场调整（比赛内可热替换的一切）

| 调整 | 时机限制 | 生效延迟 |
|---|---|---|
| 心态 7 档 | 任意死球 | 即时 |
| 攻防单项指令 | 任意死球 | 即时 |
| 角色切换 / 职责调整 | 死球 | 该球员到达下一锚点 |
| 换人（≤5） | 死球（我方球权或对方进球后） | 走到边线交接 |
| 个体指令：盯人、逼抢某人、留后不插上、拉宽/内收 | 死球 | 即时 |
| 战术喊话（士气脉冲） | 半场 / 进球后 / 落后 2 球 | 视士气模型 |

**没有暂停键**——所有调整在死球窗口生效，还原真实教练的约束（这本身是玩法张力来源）。支持玩家预设"条件规则"（如：75 分钟仍领先 → 自动收缩），这是 AI 经理同一套规则的另一面。

## 八、战术编译器（Tactics → SimParams）

> SimParams 的**权威字段契约**见 [schemas/simparams.schema.json](../schemas/simparams.schema.json)（仿真层同步产出），下表字段名与之一致。

编译器把上面所有面板数据翻译为仿真核的一张**扁平参数表**（节选核心映射）：

| 面板项 | SimParams 字段（示意） |
|---|---|
| 心态+防线高度 | `defLineBase: float (m)`, `defLineStretch: float` |
| 心态+逼抢强度 | `pressTriggerLine: Zone`, `pressTriggerDist: m`, `pressCount: int` |
| 出球方式 | `buildup: {shortPassBias, longBallWeight, gkDistribution}` |
| 节奏 | `decisionWindow: seconds`, `forwardRisk: float` |
| 反抢/反击 | `counterPressRadius: m`, `counterWindow: s`, `transitionBias` |
| 11 个角色 | `roles[11]: {anchorFn, onBallWeights, offBallRules, pressPriority}` |
| 越位战术 | `offsideTrap: bool` → 后卫线协同逻辑开关 |
| 定位球 | `setPieces: {cornersAtk: PlayScript, ...}` |

编译器还负责**可行性检查**：角色与位置槽位匹配度、职责组合冲突（例如 11 人全进攻职责会警告）、角色与球员属性适配度评分（提示玩家"这个人不适合踢节拍器"）。

## 九、战术熟练度

- 队伍级 `familiarity ∈ [0,1]`：对当前战术包的熟练度，每打一场 +0.05，改变阵型 −0.1。
- 引擎效果：全队站位误差 ×(1 + 0.3×(1−familiarity))、跑位协同（传跑时机匹配）概率 −(1−familiarity)×20%。
- 比赛日版本简化：新开档时各队按"打法风格"预置熟练度（如曼城系高位传控 0.85，防守反击队对反击包 0.9）。

## 十、数据 Schema 与生产

战术面板的全部内容都已落成**机器可读数据**（与 01 文档 §十一的球员数据同级别对待）：

| 文件（data/tactics/） | 内容 |
|---|---|
| [formations.json](../data/tactics/formations.json) | 10 套预设阵型 × 11 槽位（位置码 / 锚点坐标 / 默认职责） |
| [roles.json](../data/tactics/roles.json) | 27 个角色行为包：锚点偏移、有球权重、无球跑位、防守职责、属性适配度 |
| [mentality.json](../data/tactics/mentality.json) | 心态 7 档预设（§二表格的机读版） |
| [instructions.json](../data/tactics/instructions.json) | 有球 7 条 + 无球 10 条指令：档位 → 编译目标（§三/§四的机读版） |
| [set_pieces.json](../data/tactics/set_pieces.json) | 定位球预设目录（§六的机读版） |
| [examples/ARS_4231_high_press.json](../data/tactics/examples/ARS_4231_high_press.json) | 完整示例战术包（真实阵容，含定位球主罚顺位） |

- **战术包 = 可序列化 JSON**：`formation / mentality / instructions / roles / lineup / set_pieces / player_overrides / familiarity`，坐标与词表约定见 [data/tactics/README.md](../data/tactics/README.md)。
- 编译目标 SimParams 的权威字段契约：[schemas/simparams.schema.json](../schemas/simparams.schema.json)。
- 生产方式：**预设库组合**而非自由编辑（阵型拖拽编辑器放 v2）——阵型 10 选 1 + 角色/职责指派 + 指令勾选 + 定位球预设，覆盖 90% 需求；AI 经理与玩家共用同一战术包格式（原则 3）。
- 数据校验：`python scripts/validate_tactics.py`（阵型槽位/坐标范围/角色词表/指令档位/示例战术包的角色-槽位-球员位置兼容性）。
