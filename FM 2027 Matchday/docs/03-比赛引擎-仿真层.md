# 03 · 比赛引擎 · 仿真层（Simulation Core）

这是整个项目的心脏，也是最难的部分。原则先行：

- **确定性**：固定种子 + 固定步长，无 wall-clock。同一场比赛可精确重放，改动任何属性可 diff 对比。
- **Headless 可批量**：无渲染依赖，控制台跑 1000 场出统计。
- **分层决策**：三个频率层各管各的，模拟真实足球"教练→小组→个人"的决策结构。

## 一、时间结构

| 层 | 频率 | 职责 |
|---|---|---|
| 物理/个人决策 tick | **25Hz**（40ms） | 球员移动、球物理、持球个体决策、对抗解决 |
| 小组协作层 | 5Hz | 局部配合：传跑时机、围抢结构、防线协同 |
| 团队层 | 1Hz | 比赛阶段识别、阵型形状、攻守转换策略 |
| AI 经理层 | 事件驱动 | 心态/换人/变阵（读比分、时间、xG、疲劳） |

- 90 分钟比赛可加速运行（实时 / 2× / 4× / 仅看进球），确定性不受影响。
- 呈现层以 50–60fps 渲染 25Hz 状态流的插值（详见 04 文档）。

## 二、比赛状态机

```
开球 → 运动战 ⇄ {界外球, 球门球, 角球, 任意球, 点球, 门将持球}
        运动战 → 进球 → 庆祝 → 开球
        运动战 → 犯规 → 任意球/牌 | 受伤 → 处理 → 继续/换人窗口
任意 → 半场 → 全场（含伤停补时，由真实停表事件累计：进球/换人/伤停）
```

- 每个死球状态有**重开规则**（时限、合法位置），AI 会用快发任意球/界外球这类真实行为（受决策层评估，不是脚本）。
- 裁判模块：犯规判定（§对抗解决）→ 危险区域/动作烈度 → 牌；优势规则（进攻有利时延迟吹罚）；补时由停表事件累计。

## 三、球物理

- 参数：质量 430g、半径 0.11m、空气阻力、马格努斯力（自旋 → 弧线）。
- **所有触球事件由"执行模型"给出初速度+旋转+方向误差**（见 §执行模型），之后球走纯物理——这意味着弧线球、贴地斩、过顶球都是物理结果，不是动画标签。
- 球与草皮的滚动摩擦、反弹；雨天滚动更快、弹跳更死（配合天气系统）。

## 四、球员运动模型

身体属性 → 运动参数的直接映射：

```
v_max     = f(Pace) × 疲劳系数 × (持球 ? f(Dribbling)折扣 : 1)
a_max     = f(Acceleration)
转向速率   = f(Agility, Balance)      —— 转向半径随速度增大
对抗强度   = f(Strength, Balance)     —— 见 §对抗解决
```

- 移动采用**转向意图 + 运动学约束**：AI 给出目标点与期望速度，运动模型限制"物理上能达到什么"——快的球员真的能跑赢。
- 冲刺消耗疲劳（§疲劳），冲刺后有一段速度恢复期（模拟无氧间歇）。
- 碰撞：球员间最小间距 + 对抗事件化（不做人体穿透物理）。

## 五、对抗解决模型（Event-based，不做连续物理推挤）

| 对抗类型 | 输入 | 分辨 |
|---|---|---|
| 抢断 vs 盘带 | Tackling+Agility+Balance+站位角度 vs Dribbling+Agility+Balance+距离 | 成功→球权转移/弹出；失败→过人；边缘→犯规判定分支（抢断强度/Aggression/Dirtiness） |
| 空中对决 | Jumping Reach+Heading+时机(Anticipation) 双方 | 胜者获得处理权（按 Heading 决定顶球质量） |
| 肩部对抗 | Strength+Balance + 重心动量 | 强者挤到位置；摔倒概率（Bravery/平衡） |
| 封堵 | Bravery+反应距离 | 封堵成功=挡出；失败=穿过；极端=伤停事件 |

所有对抗解算在单个 tick 内完成并产出事件（含犯规/牌分支），呈现层只负责演出结果。

## 六、执行模型（把技术属性变成误差）

传球、射门、传中、解围共用一套结构：**意图（决策层给出）+ 执行（属性给出误差）**。

```
执行误差 = 基础误差(动作类型, 距离, 球速)
         × 用脚系数(顺足 1.0 / 逆足 1.3–1.6，按逆足脚质量插值，见 01 §十)
         × 压力系数(Composure, 逼抢接近度)      —— 镇定差的人高压下明显更慌
         × 条件系数(疲劳, 天气, 场地)
采样得到：方向误差角 δθ、力度误差 δv、触球点偏差
```

- **传球**：误差 → 落点偏差；接球方 First Touch 决定触球后球离脚距离（偏差大=被反抢机会）。
- **射门**：误差 → 球门平面上的落点分布（射正/偏出/中框）；射门质量基准由机会类型（单刀/抢点/远射/混乱球）与干扰度决定。
- **传中**：落点误差半径（Crossing）→ 后续空中对决自然分出好球坏球。
- 好处：**xG、射门分布、传球成功率都是涌现结果**，不是查表。

## 七、持球决策模型（AI 的心）

持球球员每 tick 评估动作集：

```
A = { 直塞, 短传安全球, 横传转移, 长传换边, 过人, 盘带推进, 护球, 射门, 解围, 回传 }
score(a) = P(成功|a) × V(结果|a) × 战术权重(a|角色,阶段) × 属性调制(a) + noise(Decisions, Composure)
```

- **P(成功)** 由执行模型与防守者位置计算（视野范围内）。
- **V(结果)**：传球收益 = 接球者的空间价值场（到球门、到队友的威胁度）；射门收益 = 机会质量场。
- **视野 Vision 决定"看得见哪些选项"**：视野外的队友传球线路不在候选集里——这就是"中场大师"和"工兵"在同一引擎里的本质区别。
- **噪声由 Decisions/Composure/Concentration 调制**：属性差的球员会"选错"而不是"执行差"，两类失误在观感上可区分。
- **战术权重** 来自 SimParams（心态/指令/角色覆盖/球员特性 Traits），保证战术真的改变行为，而非仅改变站位。
- 决策间有**惰性/惯性**（连续动作偏好），避免逐 tick 抖动。

## 八、无球 AI

**进攻跑位**（Off the Ball 驱动）：
- 目标点 = 角色锚点（球位函数）+ 空间价值梯度（找空当）+ 跑位规则触发（斜插、套边、回撤接应、二点包抄、decoy 跑动吸引防守）。
- **传跑协同**（5Hz 层）：传球者的候选线路与跑位者的起跑时机做匹配（给提前量），Teamwork/熟练度影响匹配质量——这是"传控好看"的来源。

**防守**（Positioning 驱动）：
- 基准位 = 防线/中场/进攻三线的形状函数（阵型锚点 + 球位弹性偏移 + 压缩度）。
- **逼抢结构**（5Hz 层）：触发条件满足（进入逼抢区域、坏触球、回传、边线陷阱）→ 指定 1–3 人上抢，同时最近者**落位 shadow cover 堵传球线路**，其余人按优先级补位——压迫有结构，不是全员疯抢。
- **越位协同**：防线 4 人共享上提决策（Communication/领导力影响同步误差），开=主动造越位。

## 九、团队 AI（1Hz）

- **比赛阶段识别**：我方 {组织 → 推进 → 进攻}，无球 {高位压迫 / 中场拦截 / 低位防守块}，转换 {反抢窗口 / 阵地回撤}。
- **形状计算**：把阵型锚点映射到实际站位（球位偏移 + 压缩度 + 宽度指令），输出 11 人目标位给个人层。
- **风险控制**：比分×时间 → 全局风险预算（落后 75' → 风险预算拉满：边后卫内收成 3-2-5 之类的真实模式可以涌现）。
- **攻守转换**：反抢（SimParams 开关）失败 → 按触发线选择就地反抢或整体退防；反击触发 → 指定前插三人组与出球人。

## 十、AI 经理模块（"比 FIFA 聪明"的载体之一）

每队一个独立决策体，与玩家共用战术接口：

- **赛前**：读对手画像（阵型、逼抢习惯、速度/身高分布）→ 选择阵型/心态/针对性（如：对手中卫转身慢 → 突前前锋 + 直传）。
- **临场**：每 5 分钟评估 {比分差, 剩余时间, xG 差, 体能, 红黄牌, 伤病} → 决策表：换人（对位/胜势/败势三类逻辑）、变阵、心态调整、逼抢强度调整、犯规战术（保护领先）。
- 可解释：决策附带理由标签，供 UI 弹幕/解说使用（"70 分钟，主帅用 Foden 换下体能见底的 B2B 中场"）。

## 十一、疲劳、天气与场地

- **疲劳**：消耗 = 跑动强度×位置系数（B2B 高、中卫低）；效果：v_max/a_max 下降、Concentration 走神率上升、误差系数上升。自然 Fitness 决定曲线形状。
- **天气**：雨 → 传球误差 ×1.15、GK Handling 惩罚、地面球速快；风 → 长传误差；夜场/灯光仅呈现层。
- **场地**：草皮质量 → 传球误差小系数（v1 常量，v2 可动态恶化禁区）。

## 十二、定位球系统

- 走位部分：**脚本化**（SimParams 里的 PlayScript：每人一条相对跑位轨迹，相对球与门框定义）。
- 执行部分：**属性化**（主罚质量、争顶对决、头球质量全走通用模型）。
- 快发决策：AI 可选择快发（当防守未落位时收益最高，Decisions 决定是否"看到"这个机会）。

## 十三、状态流（Sim → Presentation 的唯一接口）

```json
{
  "tick": 104320, "phase": "open_play", "clock": "63:12",
  "ball": { "p": [52.3, 33.1, 0.4], "v": [18.2, -3.1, 2.0], "spin": [0, 40, 0] },
  "players": [
    { "id": 7, "p": [50.1, 34.0], "heading": 92, "speed": 6.8,
      "action": "dribble", "has_ball": true, "stamina": 0.61 }
  ],
  "events": [ { "type": "pass_attempt", "from": 7, "to": 10, "quality": 0.83 } ]
}
```

- 坐标系：米制，标准场 105×68。状态流同时落盘 → **回放系统免费获得**（拖动条、任意机位重放）。
- 本结构的**权威 Schema** 见 [schemas/state_stream.schema.json](../schemas/state_stream.schema.json)；事件 `type` 词表见 [schemas/telemetry_events.json](../schemas/telemetry_events.json)（遥测/转播导演/图文包装/音频同源引用）。
- 遥测（旁路输出）：事件流（传球/射门/对抗/跑位触发），供统计校准与赛后图文（xG 曲线、传球网络、热图）。

## 十四、验证与校准（M0/M1 的验收标准）

**统计对齐**（批量 ≥1000 场，对照 StatsBomb 开放数据的英超量级）：

| 指标（机读 id） | 真实英超量级 | 验收 |
|---|---|---|
| 场均进球 (goals_per_match) | 2.6–3.0 | 落入区间 |
| 场均射门 / 射正 (shots_per_match / sot_per_match) | 11–13 / 4–5 | 落入区间 |
| 传球成功率 (pass_accuracy_pct) | 78–86%（按风格分化） | 落入区间 |
| 场均角球 / 犯规 / 黄牌 (corners / fouls / yellows_per_match) | 5±2 / 10–13 / 3–4.5 | 落入区间 |
| 控球率 vs 排名相关性 (possession_rank_corr) | 传控强队偏高 | 正相关 |

**战术敏感性测试**（每条都是一个"可教练化"用例，AI 聪明的证据；机读版见 [data/calibration/tactics_sensitivity.csv](../data/calibration/tactics_sensitivity.csv)）：

1. 超高防线 vs 速度型突前前锋 (high_line_vs_pace) → 高位线被打身后的进球显著上升。
2. 低位块 vs 缺乏创造力的队 (low_block_vs_sterile) → 进球稀少、定位球占比上升。
3. 反抢包 vs 出球弱队 (counter_press_vs_weak_buildup) → 前场夺回球权次数与转化显著上升。
4. 突前前锋 vs 造越位开关 (offside_trap_vs_af) → 越位次数上升且伴随后卫线失误风险。
5. 内锋（逆足）阵 (inverted_wingers) → 远射/小禁区倒三角得分模式出现。
6. AI 经理落后时 (ai_manager_chasing) → 70' 后边后卫内收、高空轰炸等真实模式在遥测中出现。

这些用例写成自动化测试：**战术改一个参数 → 批测 500 场 → 分布必须显著移动**。这就是"AI 比 FIFA 聪明"的可量化定义：FIFA 的 AI 对战术输入的响应是浅层的、常可被一招打穿；我们的验收标准是战术输入与涌现结果之间有真实、多样、互克的因果链。

## 十五、接口 Schema 与校准数据

仿真核的两条对外边界都已落成机器可读契约，改任何一侧必须先改 schema：

| 文件 | 边界 | 内容 |
|---|---|---|
| [schemas/simparams.schema.json](../schemas/simparams.schema.json) | 战术编译器 → 仿真核 | 扁平参数表（02 §八 的权威化）：心态/防线/逼抢/出球/节奏/反抢反击/越位/11 角色编译结果/定位球/熟练度 |
| [schemas/state_stream.schema.json](../schemas/state_stream.schema.json) | 仿真核 → 呈现层 | 每 tick 状态流（§十三 的权威化）：25Hz 位置/朝向/速度/动作/体能 + 事件数组 |
| [schemas/telemetry_events.json](../schemas/telemetry_events.json) | 遥测旁路（横切） | 22 个事件类型的词表：字段定义 + 消费方（遥测/转播导演/图文/音频/UI）；呈现层配置里引用的事件只能出自它 |

校准数据在 [data/calibration/](../data/calibration/)：`epl_baseline.csv`（§十四统计对齐基线）与 `tactics_sensitivity.csv`（§十四条目机读版），消费方式见其 [README](../data/calibration/README.md)。M0/M1 的验收就是：批量跑场 → 对照这两份机读目标自动判定。
