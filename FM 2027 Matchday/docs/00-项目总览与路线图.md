# FM 2027 Matchday — 项目总览与路线图

## 一句话定位

**FM 的战术深度 × FIFA 的转播级画面 × 比 FIFA 更聪明的纯 AI 对抗。**

玩家扮演英超球队经理：赛前布置战术、临场指挥（调整心态/换人/针对性指令），但**场上 22 名球员没有任何人为操控**，全部由 AI 驱动。支持纯观战模式（两边连经理也是 AI，看"教练斗法"）。

## 范围界定

| 内容 | 本项目 | 明确不做（后续版本再议） |
|---|---|---|
| 球队 | 英超 20 队一线队（约 25 人/队，共约 500 名球员） | 青年队、预备队、其他联赛 |
| 玩法 | 比赛日：赛前战术、临场指挥、观赛 | 转会、青训、财政、多赛季生涯 |
| 引擎 | 完整仿真 + 3D 呈现 | — |

这个范围的含义：**比赛引擎就是游戏本体**，所有资源应该集中在「球员数据模型 → 战术系统 → 仿真核 → 呈现层」这条主线上。

## 三大支柱与对应文档

1. **球员属性系统** → [01-球员属性系统.md](01-球员属性系统.md)
   沿用 FM 玩家熟悉的 1-20 三分类（技术/精神/身体）+ 门将专属 + 隐藏属性，核心增量是**每个属性都映射到引擎参数**——不是贴标签，而是直接参与物理与决策计算。
2. **战术系统** → [02-战术系统.md](02-战术系统.md)
   完全参考 FM 的心智模型（阵型/心态/角色职责/攻防指令/定位球/临场调整），底层把战术面板**编译**成仿真核可执行的参数包，支持比赛内热更新。
3. **比赛引擎** → [03-比赛引擎-仿真层.md](03-比赛引擎-仿真层.md) + [04-比赛引擎-视觉与呈现.md](04-比赛引擎-视觉与呈现.md)
   架构上**仿真与呈现彻底分离**：headless 确定性仿真核（25Hz）产出状态流，呈现层消费状态流做渲染、转播导演、图文包装。

## 总体架构

```
┌─────────────────────────────────────────────────────────┐
│ 数据层（JSON/CSV）                                        │
│  500 名球员属性 · 20 队 · 阵型/角色库 · 定位球套路库        │
└──────────────────────┬──────────────────────────────────┘
                       ▼ 战术编译器（Tactics → SimParams）
┌─────────────────────────────────────────────────────────┐
│ 仿真核 Simulation Core（headless，引擎无关，确定性）        │
│  25Hz · 团队AI(1Hz) / 小组协作AI(5Hz) / 个人AI(每tick)     │
│  球物理 · 对抗解决 · 裁判 · 疲劳 · 天气 · AI经理            │
│  输出：状态流（位置/朝向/动作/事件）+ 遥测（可批量跑1000场）  │
└──────────────────────┬──────────────────────────────────┘
                       ▼ 状态流 State Stream（tick 级）
┌─────────────────────────────────────────────────────────┐
│ 呈现层 Presentation（Unity 6 / URP）                      │
│  动画控制（球-脚同步）· 转播导演（自动机位）· 图文包装        │
│  人群/音频反应 · 回放系统 · UI                              │
└─────────────────────────────────────────────────────────┘
```

## 五条核心设计原则

1. **仿真与呈现彻底分离。** 仿真核是引擎无关的库，可以丢掉画面在控制台跑 1000 场做统计校准；呈现层坏了不影响比赛结果；将来想换引擎、加 "仅看精华" 模式、做回放拖动条，都不用动 AI。
2. **属性全映射。** 每个属性必须对应一个物理参数或决策参数，并在遥测里能观察到它的影响。杜绝"属性只是数字"的 FM 老问题。
3. **战术即数据。** 战术 = 一个可序列化的参数包，比赛进行中可以热替换（换人、变阵、改心态）。玩家界面和 AI 经理模块调用**同一套接口**，保证"AI 会用它自己的战术打赢你"。
4. **确定性。** 固定随机种子 + 固定步长 → 任意比赛可精确回放、可 diff 调试（改一个属性，回放两遍对比差异）。
5. **足球先于画面。** AI 与比赛逻辑先在 2D 调试画面里做对（统计分布对齐真实英超数据），再上 3D 呈现。画面是放大器，不是地基。

## 与竞品的关系

| | FM24/26 | FIFA / FC26 | 本项目 |
|---|---|---|---|
| 战术深度 | ★★★★★ | ★★（滑条+预按键） | ★★★★★（FM 心智模型） |
| AI 决策拟真 | 好（但过程不可见） | 浅，有可利用模式（cutback 流） | 目标：可验证的、教练可影响的 AI |
| 画面 | FM26 大幅进步（Unity），仍偏生硬 | 顶级 | 目标：转播级呈现（镜头语言+图文包装），单场景可及 FIFA 观感 |
| 玩家角色 | 经理 | 球员 | 经理（场上无人操控） |

FM26 的比赛引擎已被媒体评为系列最大进步，但社区普遍抱怨"看起来更漂亮、玩起来更机械、可预测"。我们的机会：**在它之上做可验证的 AI 深度 + 更强的转播呈现**（画面观感的一半来自镜头语言和图文包装，这部分是工程问题不是美术预算问题，小团队可以打赢）。

## 技术选型建议

| 部分 | 建议 | 理由 | 备选 |
|---|---|---|---|
| 仿真核 | C#（独立程序集，无 Unity 依赖） | 与呈现同语言，可直接在控制台跑批测 | Rust/C++ 核心 + FFI（性能上限更高，迭代慢） |
| 呈现层 | **Unity 6 + URP** | 足球动画包/球场/人群资产生态最好；C# 同语言；FM26 自己也用 Unity | Unreal 5（画面上限更高，团队有 3D 人才时选它） |
| 数据 | JSON + CSV 管线，SQLite 运行库 | 简单、可 diff、可脚本批量生成/修改 | — |
| 校准数据 | StatsBomb 开放事件数据、SkillCorner/Metrica 开放追踪数据 | 免费，用于把仿真统计分布对齐真实足球 | — |

版权注意：开发期可内部使用真实球员名做校准参照；**发布时球员一律化名/生成**（FM 自家也是先有数据库授权才有真名），UI 上做 "Premier Division" 虚构联赛。

## 里程碑

| 阶段 | 时间（估） | 内容 | 验收标准 |
|---|---|---|---|
| M0 数据与规则 | 1–2 月 | 属性 schema、500 人数据 v0、战术参数包格式、仿真核 v0（粗粒度回合级） | 1000 场统计（进球/射门/xG/控球）落在真实英超合理区间；强队胜率显著高于弱队 |
| M1 仿真核 v1 | 3–5 月 | 25Hz 个体仿真 + 2D 调试渲染器、战术编译器 v1（10 阵型/20 角色）、压迫与转换模型 | 2D 画面下比赛"像足球"；战术敏感性测试通过（详见 03 文档 §验证） |
| M2 呈现 v1 | 6–9 月 | Unity 3D 呈现：1 座球场、动捕动画库、球-脚同步、转播导演 v1、图文包装 v1 | 3D 观感明显优于 FM26 的 ME（盲评） |
| M3 AI 经理与打磨 | 10–12 月 | AI 经理临场决策（换人/变阵）、定位球套路、天气、音频反应、回放系统 | 纯 AI vs AI 观赏性测试：观众能看出"两队打法不同、有教练斗法" |
| M4 发布准备 | +3 月 | 化名数据切换、性能优化（中端机 60fps）、20 队完整数据 | — |

## 风险清单

| 风险 | 等级 | 对策 |
|---|---|---|
| AI 不"像足球"（最难的部分） | 高 | M0/M1 阶段全部投入；用真实比赛统计分布做量化验收；每个战术行为写"可教练化"测试用例 |
| 动画预算（接近 FIFA 画面） | 高 | 只做一个联赛一个球场；买动捕库+资产商店；靠镜头语言与图文包装补观感；签名动作后期再加 |
| 范围膨胀 | 中 | 严格按里程碑；生涯/转会/青训全部砍掉 |
| 球员授权 | 中 | 化名方案从第一天就设计进数据 schema |
