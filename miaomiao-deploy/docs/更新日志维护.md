# 📜 更新日志维护说明

游戏内「更新日志」面板的数据在 **js/changelog.js**，玩家可以在主菜单点「📜 更新日志」查看；
有没看过的新版本时，进游戏会**自动弹出最新一期的更新内容**（localStorage 记忆已看版本，
关闭面板即视为已读）。

## 发新版本时的流程（3 步）

1. **升版本号**：把 `index.html` 里所有脚本标签的 `?v=` 缓存号升一位（如 `20260908b` → `20260908c`）。
2. **加日志条目**（二选一）：
   - 自动：`node tools/gen-changelog.js` —— 工具会把上次记录之后的 git 提交按
     新增/优化/平衡/修复 自动归类，生成一条以今天为日期的新条目；
   - 手写（措辞更可控，推荐正式发版用）：
     `node tools/gen-changelog.js --title "标题" "新增：xxx" "修复：yyy"`（省略类型前缀默认算「优化」）。
3. **润色**（可选）：直接编辑 `js/changelog.js` 调整措辞。改完记得提交代码。

> 提交代码本身也会产生新提交——建议顺序：先提交游戏改动，再跑生成器，最后把 changelog.js 的更新一起提交。

## 条目怎么写（颗粒度约定）

和普通游戏的更新公告保持一致，**玩家视角**，一句话说清「改了什么、现在怎么样了」：

- ✅ 「修复了在手机上游玩时画面大小异常的问题」
- ✅ 「调整了游戏平衡，角色不会再一刀打倒头目」
- ✅ 「新增六张夜巡地图」
- ❌ 不写内部实现：「canvas CSS 尺寸与视口同步」「把 roundHpMul 从 3 改成 2.5」
- ❌ 不写具体某个 bug 的技术细节，只说玩家能感知到的现象和结果

类型标签：`new 新增` / `opt 优化` / `bal 平衡` / `fix 修复`。

## 机制备忘

- 面板 UI 在 `js/changelog_ui.js`，与数据分离；工具只重写 `js/changelog.js`。
- `lastCommit` 字段是工具的记账（已收录到哪个提交），请勿手改；工具每次运行后推进到当前 HEAD。
- 自动弹窗只在 `location.search` 带 `?auto=`（自动化测试）时跳过，其余情况有新版本就弹。
- 同一版本号再次生成时会**合并**进已有条目，不会出现重复版本块。
